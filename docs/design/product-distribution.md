# 제품 유통 목표 (범위·세대·금지)

> **역할:** 대회 MVP 이후, **무엇을 제품으로 유통할지**만 고정한다.  
> **일정 정본 아님.** 대회 일정은 [`../ops/contest-submission-checklist.md`](../ops/contest-submission-checklist.md).  
> **진입조건·Phase 산출물**은 [`roadmap.md`](./roadmap.md). 결정 근거는 [`../context-handoff.md`](../context-handoff.md) **D19**.  
> 갱신: 2026-08-10

---

## 1. 한 줄

**CapNet = Open Agent + (선택) Open Compute + User-defined Trust Domain.**  
경제 인센티브는 **선택 레이어**이며 제품의 기초가 아니다.

지금 유통 가능한 1호 제품은  
**「초대된 team/tenant 플릿에서, 능력만 요구하면 승인 도메인 안 기기로만 돌리고 증적이 남는 실행 계층」**  
이다.  
**「아무 사용자가 아무 데이터를 아무 Node에」** 는 이 세대의 제품이 아니다.

---

## 2. 보장 / 불보장 (유통 카피 정본)

| 보장한다 | 보장하지 않는다 |
|----------|-----------------|
| 승인하지 않은 `trust_domain`으로 **라우팅되지 않는다** (FK) | Node가 데이터를 **남기지 않는다** (TEE 없이 원리적으로 불가) |
| 사용자는 **기기 주소를 몰라도** 된다 | 두 Agent가 **같은 답**을 낸다 |
| 누가·무엇으로·언제 실행했는지 **증적이 남고 조회된다** | Private Community만으로 **기밀이 암호화·격리**된다 |
| 게이트를 붙인 Capability에서는 미통과 Agent에 **할당 불가** | 모든 실행 결과가 **수학적으로 참**이다 |

**Private Community ≠ 데이터 안전.**  
커뮤니티·도메인은 **누가 실행할 수 있는가**이고, 샌드박스·TEE·암호는 **실행 Node가 평문을 어떻게 보는가**이다. 둘을 섞어 쓰지 않는다.

---

## 3. 신뢰 경계 (사용자가 고른다)

스키마 정본: `team` · `tenant` · `public` (`docs/spec/schema.sql` · `domain_compatible`).

| 경계 | 쓰는 데이터 | Node | 경제 |
|------|-------------|------|------|
| **team** | 시연·내부 검증 | 팀 조달 | 없음 |
| **tenant** | 조직 허용 데이터 | 초대·조직 플릿 | 조직 IT 예산 (정산 모듈 아님) |
| **public** | **저민감만** (예: 공개 이미지 분류) | 등급화·격리 전 **대규모 의존 금지** | 상호부조는 가능하나 **가용성 보장 없음** |

기획서 §8.1-1: **공공 유휴에 보상 없이 의존하지 않는다.**  
Public 풀을 “무료라서 안전·충분하다”고 유통 주장하지 않는다.

---

## 4. 오픈 Agent

- Agent는 플랫폼 독점이 아니다. 계약(Capability) + (선택) 품질 프로파일 + 증적으로 등록·교체한다.
- 사용자는 “모델 이름”이 아니라 **Capability + Trust Policy**로 요청한다.
- 자유 업로드·임의 코드 실행 Agent는 **격리 세대 이전**에 유통하지 않는다 (D8 · 로드맵 Phase 3+).

---

## 5. 유통 세대 (버전업 계단)

스키마 제약을 약화하지 않는다. DDL **추가**와 마이그레이션(SD-007)만.

| 세대 | 유통 목표 | 반드시 | 아직 넣지 않음 |
|------|-----------|--------|----------------|
| **v제품-0** | 범위 한정 MVP 유통 (온프레·초대) | 이 문서·보장/불보장·tenant 운용·증적 조회 | 토큰·공개 마켓·기밀 SaaS |
| **v제품-1** | 남이 Node를 믿을 수 있음 | ~~폐기~~ ✅(SD-014) · ~~tenant 운용~~ ✅(P2-1) · ~~`node_credential`~~ ✅(P2-4 · `0007`) · lease/재할당 운영화 · 기본 모니터링 | TEE·1000+ Node 스케줄러 |
| **v제품-2** | 남의 Agent 코드 | 컨테이너 격리·자원/시간/네트워크 제한·가중치 해시 폐기 | 원격 증명 완전체 |
| **v제품-3** | 규모 | 제약+비용+신뢰 스케줄러·abuse·SLA | 정산 |
| **v제품-4+** | 선택 | 기여 계측 → (필요 시) 유료/보상 | — |

**지금(문서 반영 시점):** Contest MVP + 사이클 폐쇄 ≈ **v제품-0 직전**.  
**제품 유통 착수 관문:** SD-007 → P2-1(tenant 운용) → P2-4(credential) 순 (`roadmap.md`).

---

## 6. 하면 안 되는 유통 주장

1. “아무 스마트폰에 기업 기밀을 보내도 안전하다”
2. Private Community만으로 “데이터가 유출되지 않는다”
3. 보상·격리 없는 Public Node로 “상용 가용성”
4. 골든셋 점수로 “모든 결과가 참”
5. 스키마 제약 약화로 “일단 배포”
