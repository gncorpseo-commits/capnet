# 남의 Agent 를 받는다 — 위협 모델과 격리 설계

> **역할:** v제품-2 (「남의 Agent 코드」) 로 가기 위한 위협 모델·계단·진입조건.
> Phase 3 진입조건 중 「**격리 초안**」이 이 문서다 ([`roadmap.md`](./roadmap.md) §4).
> 갱신: 2026-08-11 (초판)
>
> 관련: [`product-distribution.md`](./product-distribution.md) §4·§5 · [`capnet-plan.md`](./capnet-plan.md) §5.3 ·
> `CLAUDE.md` 절대규칙 5·7 · D8

---

## 0. 결론부터

**「남의 Agent」는 하나가 아니라 세 단계다.** 지금 우리는 1단계에 있고, 2단계는 코드로 갈 수 있으며,
3단계는 **코드로 못 가는 전제**(법무·고객)가 앞에 있다.

| 단계 | 무엇을 받나 | 위험의 성격 | 지금 상태 |
|------|-------------|-------------|-----------|
| **F1** | 남의 **가중치** (우리 아키텍처) | 자원 폭발 · 품질 미달 | ✅ 구조상 가능. **한도가 없다** |
| **F2** | 남의 **아키텍처 선언** (allowlist 안) | 자원 폭발 · 계약-실행 불일치 | ⚠️ arch 가 계약에 안 묶여 있다 |
| **F3** | 남의 **코드** (임의 실행) | 임의 코드 실행 · 데이터 유출 · 측면 이동 | ❌ 격리 없음. D8 상 유통 금지 |

**F1·F2 는 임의 코드 실행이 아니다.** safetensors 는 텐서만 담고(pickle 과 달리 로드가 코드 실행이 아니다),
아키텍처는 `ARCH_REGISTRY` **allowlist** 에서만 나온다. 이 두 성질이 지금 우리가 가진 가장 큰 자산이다.

**F3 는 성질이 다르다.** 남의 코드를 우리 프로세스에서 돌리는 순간 위 자산이 전부 사라진다.

## 1. 지금 서 있는 방어

문서가 아니라 코드·제약에 있는 것만 적는다.

| 방어 | 어디 | 무엇을 막나 |
|------|------|-------------|
| safetensors 강제 | `assert_safetensors` · `ck` weights_format | `.pt`/pickle 로드 = 임의 코드 실행 (절대규칙 5) |
| arch allowlist | `tiny_cnn.ARCH_REGISTRY` | 임의 모델 클래스 구성 |
| 입력 allowlist | `allowlist.py` · 절대규칙 7 | 자유 업로드 경로 자체가 없다 |
| 게이트 사슬 | FK 4단 | 미검증 Agent 에 배정 불가 |
| 가중치 해시 결속 | `agent_node_ready` 복합 FK | 게이트한 가중치와 다른 것을 실행 불가 |
| 게이트 러너 고정 | `ck_gate_runner_team` | 제출자가 자기 채점 불가 (절대규칙 8) |
| 신원 증서 | `node_credential` (P2-4) | Node 사칭 |
| 컨테이너 한도 | compose `mem_limit`·`cpus` | 프로세스 **전체** OOM (개별 추론이 아니다) |

## 2. 지금 비어 있는 것 (F1·F2 를 막는 구멍)

### 2.1 아키텍처가 계약에 묶여 있지 않다

`infer.py` 의 `_arch_for_weights()` 는 **Node 로컬 파일**(`<weights>.meta.json`)에서 arch 를 읽는다.

- Agent 신원은 `weights_sha256` 뿐이다. **arch 는 그 해시에 포함되지 않는다**
- 즉 Core 가 「이 Agent 는 이 arch 다」라고 말할 방법이 없고, 실행 Node 가 로컬 파일로 정한다
- 지금은 arch 가 어긋나면 `load_state_dict` 가 실패해 **터진다**(조용히 다른 모델이 도는 것은 아니다).
  그러나 「게이트가 승인한 것과 실행한 것이 같다」가 **코드로 보장되지 않는다** — 우연히 실패할 뿐이다

> 남의 Agent 를 받으면 이건 즉시 문제가 된다. 제출자가 arch 를 선언하고, **Core 가 그것을 증적에 묶어야** 한다.

### 2.2 추론에 자원 한도가 없다

`predict_image()` 에는 timeout 도, 입력 크기 상한도, thread 제한도 없다.
compose 의 `mem_limit: 1g` 는 **컨테이너 전체** 한도라, 한 건의 악성 추론이 그 Node 의 다른 lease 까지 같이 죽인다.

기획서 §5.3 이 악성 연산·OOM 을 MVP **미완화**로 두고 「팀 Node 신뢰」에 기댄다고 적었다.
**남의 Agent 를 받는 순간 그 전제가 사라진다.**

### 2.3 모델 크기 상한이 없다

가중치 파일 크기·파라미터 수 상한이 없다. 게이트는 정확도만 본다.
40장 채점을 통과하는 10GB 짜리 모델을 막을 것이 없다.

## 3. F2 까지 가는 계단 (코드로 됨)

### I1 — arch 를 계약에 묶는다 · ✅ 구현 (2026-08-11 · `migrations/0008`)

1. `agent_arch` 룩업 테이블 (허용 아키텍처 = **DB 행**, 코드 상수가 아니다).
   이 리포의 idiom 그대로다 — `compute_tier_rank`·`domain_compatible` 과 같은 「행렬 = 정책」
2. `agent.arch` → `agent_arch` FK. **없는 arch 는 Agent 등록 자체가 안 된다**
3. 배정 페이로드에 arch 를 실어 Node 로 보낸다. Node 는 **Core 가 말한 arch** 로 로드하고,
   로컬 `meta.json` 은 arch 결정에 쓰지 않는다
4. 기존 Agent 는 `arch IS NULL` 로 남긴다 (legacy). 조회면으로 드러내고 점진 백필

> **실 DB (2026-08-11):** 적용 직후 legacy 45건(라우팅 가능 35건) → **백필 후 1건(라우팅 가능 0건)**.
> 남은 하나는 `seed-agent` — placeholder 가중치라 Node 가 arch 를 모르고, 애초에 라우팅되지 않는다 (SD-015).
>
> **백필의 근거:** Core 는 가중치 파일을 보지 않으므로 추측하지 않는다.
> 가중치를 실제로 들고 있는 Node 에게 물어, `weights_sha256` 이 **일치하는** Agent 만 채웠다
> (`scripts/backfill_agent_arch.sh`). 해시가 같으면 같은 파일이므로 「어느 파일인가」는 추측이 아니다.
> 추측이 섞이는 지점은 「그 파일의 arch 가 무엇인가」뿐이고, 그건 학습 기록(`<weights>.meta.json`)이 답한다.
> **Node 의 증언이지 Core 의 독립 판정이 아니다** — 그 사실을 알고 쓴다.

### I2 — 실행 자원 한도 · ✅ 부분 구현 (2026-08-11)

| 한도 | 어디서 | 왜 | 상태 |
|------|--------|-----|------|
| 추론 wall-clock timeout | Node | 무한 루프·초장시간 연산 | ❌ 아직 |
| torch thread 수 | Node | 한 건이 CPU 를 다 먹지 않게 | ✅ `NODE_TORCH_THREADS` (기본 1) |
| 입력 픽셀 상한 | Node | 디코드 폭탄 (작은 파일 → 거대 비트맵) | ✅ `NODE_MAX_INPUT_PIXELS` + `Image.MAX_IMAGE_PIXELS` |
| 파라미터 수 상한 | `agent_arch.max_params` (DB) | 게이트 통과 후 거대 모델 스왑 | ✅ 페이로드로 전달 · **매 호출** 검사 |

> **한도는 매 호출 본다.** 로드할 때만 보면 모델이 캐시된 뒤 상한을 낮춰도 계속 돈다 —
> 구현 중 실제로 그 버그를 만들었고 실측으로 잡았다.

**timeout 이 아직 없는 이유:** 파이썬에서 CPU 바운드 연산을 안전하게 끊으려면 별도 프로세스가 필요하다.
그건 F3 의 프로세스 격리와 같은 작업이라, 거기서 함께 한다.

### I3 — 게이트에도 같은 한도 · ❌ 아직

한도가 실행에만 있으면 「게이트는 통과하고 실행은 못 하는」 Agent 가 생긴다.
채점기와 실행이 **같은 한도**를 써야 게이트가 의미를 갖는다.

## 4. F3 — 남의 코드 (여기부터 코드만으로 안 된다)

### 4.1 위협 모델이 바뀐다

| 위협 | F1·F2 | F3 |
|------|-------|-----|
| 임의 코드 실행 | 불가 (safetensors + allowlist) | **가능 — 이게 전제다** |
| 데이터 유출 | Node 가 평문을 본다 (원래 불보장) | + 외부로 **보낼** 수 있다 |
| 측면 이동 | — | Node 의 다른 lease·자격증명·호스트 |
| 자원 고갈 | 추론 한도로 방어 | 프로세스를 벗어남 |
| 증적 위조 | Core 가 기록 | Agent 가 결과를 조작해 보고 |

### 4.2 필요한 것

1. **프로세스 격리** — 컨테이너/샌드박스에서 Agent 코드 실행. 파일시스템 읽기전용·최소 마운트
2. **네트워크 차단** — 기본 egress 없음. 결과는 Core 로만
3. **자격증명 분리** — Agent 코드가 Node 증서에 접근 불가
4. **자원 cgroup** — 메모리·CPU·시간, **lease 단위**로
5. **결과 경계** — Agent 는 결과를 「제안」하고 Node 가 계약 스키마로 검증해 보고
6. **가중치 해시 폐기 경로** — 나쁜 것으로 판명된 아티팩트를 끊는다 (SD-014 의 폐기와 같은 성질)

### 4.3 코드로 풀 수 없는 전제 (로드맵 §4.1)

| 전제 | 성격 | 지금 |
|------|------|------|
| 법무 킥오프 | 계약·책임 | ❌ 미착수 |
| 테넌트 고객 1곳 | 영업·검증 | ❌ 0건 |
| 거주지 요구 실재 확인 | 시장 인터뷰 3–5건 | ❌ 0건 |

기획서 §13: 시장 근거가 비어도 기술 Go 는 가능하나 **「고객 대화 0건」이면 Product Track 착수 보류**로 적는다.

> **D8 은 그대로다:** 자유 업로드·임의 코드 실행 Agent 는 **격리 세대 이전에 유통하지 않는다.**
> 이 문서는 그 금지를 푸는 문서가 아니라, **무엇을 갖추면 풀 수 있는지**를 적는 문서다.

## 5. 하면 안 되는 주장

`product-distribution.md` §6 에 더한다.

1. 「allowlist 아키텍처라서 남의 코드도 안전하다」 — **아니다.** F2 와 F3 는 다른 문제다
2. 「컨테이너에 넣었으니 격리됐다」 — egress·마운트·자격증명이 남아 있으면 격리가 아니다
3. 「게이트를 통과했으니 안전하다」 — 게이트는 **품질** 판정이지 **안전** 판정이 아니다
4. 「증적이 남으니 위조를 막는다」 — 증적은 사후 추적이지 사전 방어가 아니다

---

## 6. 이 문서가 닫는 것

Phase 3 진입조건은 「격리 초안 + 법무 킥오프」다. 이 문서가 **초안** 쪽을 채운다.
법무·고객은 코드가 아니므로 여전히 열려 있고, 그 사실이 이 문서의 결론이기도 하다.

I1·I2·I3 는 **F3 없이도 값이 있다** — 지금 팀 Agent 에 대해서도 계약-실행 결속과 자원 한도는 필요하다.
그래서 먼저 한다.
