# 사람(팀) 개입 · AI 보조 — 역할 정리

> **목적:** 붙임2 「상용 AI 보조 / 팀이 설계」 문장의 근거를, 기억에만 의존하지 않고 **저장소 문서에서 재구성**한다.  
> **한계:** 커밋 author는 역할 서명(finn/toma/pl)이라 “누가 타자쳤는지”는 알 수 없다. 여기서 말하는 **개입**은 **결정·판정·범위·반증·제출 운영**이다.  
> **갱신:** 2026-08-25 · 근거 정본 [`../context-handoff.md`](../context-handoff.md) · [`../ops/phase1-verdict.md`](../ops/phase1-verdict.md) · [`../bridge/PROTOCOL.md`](../bridge/PROTOCOL.md)

기억과 다르면 이 파일을 고친다. AI가 “당신이 했다”고 단정한 줄이 아니라, **문서에 남은 흔적**이다.

---

## 0. 한 장 요약

| 구분 | 사람(팀) 개입 | AI 보조가 큰 영역 |
|------|----------------|-------------------|
| **무엇을 만드는가** | 제품 주장 · 불변식 · 판정 기준 · 범위(Non-goal) | API·스크립트·테스트·문서 초안 구현 |
| **어떻게 확정하는가** | D-결정 · 브리지 Decision/Confirm · master 머지 | Proposal 초안 · 패치 PR |
| **무엇이 틀렸는가** | 반증을 인정하고 계약을 개정(D17·D18) · 한계를 보고서에 남김 | 재측정 스크립트·표 정리 |
| **출품** | 촬영·편집·양식 문장 취향·포털 | 런북·초안 문장·docx 채우기 스크립트 |

**한 줄:** 사람은 **규칙과 판정**을 정하고 지켰고, AI는 **그 규칙을 코드로 옮기고 검증 루프를 돌리는 데** 쓰였다.

## 1. 사람이 개입했다고 문서에 남는 것

### 1.1 출발점 · 제품 정의 (기획·서사)

문서·대화에서 반복해 고정된 **왜**다. 구현 세부가 아니라 **무엇을 팔지**다.

| 개입 | 내용 | 근거 위치 |
|------|------|-----------|
| 실행 계층 | 서버 주소 호출이 아니라 **능력(Capability)만 요청** | 기획서 §1 · D18 · 보고서 소개/배경 |
| 변별점 | “잘 도는 GPU 풀”이 아니라 **승인 밖 라우팅 불가 + 증적** | D15 · D11(M25 Must) |
| 범위 | MVP = **승인된 팀 Node 플릿** 검증. 공개 유휴망·TEE는 이후 | D7 · D19 · 한계점 절 |
| 금지 | 사전학습 가중치 금지 · safetensors만 · 비통제 수집 기각 | D5 · D6 · D8′ |
| 절대 규칙 | 제약 약화 금지 · `INSERT…SELECT` · Node 자기등급 주장 금지 · 게이트는 team runner만 | [`CLAUDE.md`](../../CLAUDE.md) |

최근 보고서 문장(“유휴 자원이 있어도 **무엇을 어디서 돌려도 되는지**가 문제”)도 같은 줄기다 — **구현 전에 방향을 잡는 개입**.

### 1.2 스키마·라우팅 불변식 (설계 결정)

“SQL을 누가 쳤는가”가 아니라 **어떤 상태를 불법으로 둘지**를 정한 것.

| 개입 | 한 줄 | D# |
|------|--------|-----|
| DB가 판정 | 앱 if로 라우팅하지 않음 · 복합 FK·호환 행렬 | (스키마 정본 + pitfalls) |
| 배정 스냅샷 | `assignment`/`gate_run`은 앱이 숫자 넣어 INSERT 금지 | 절대규칙 2 |
| 티어 | 텍스트 `L<M<S` 비교 금지 → `tier_compatible` | 절대규칙 3 |
| 게이트 장소 | 제출자 Node에서 골든 돌리면 게이팅 무력화 → **team runner만** | D4 |
| 입력 | 서명 URL·fileToken **기각** · Core 중개만 (2안) | D8′ · D22 |
| 품질 프로파일 | 골든을 계약에서 분리 · FK/NOT NULL **끄지 않고** 센티널로 풂 | D18 · D20 |
| 조직 | `trust_domain`≠조직 → org 분리 (A→B 기기 배정 **실측 후**) | D24 |
| 증적 절반 | task에 요청자·요청 도메인 기록 (하드코딩 seed 제거) | D23 |

브리지 규칙상 **DDL·정책 숫자·제품 주장**은 Decision급 → 사람 Confirm 없이 구현하면 안 된다 ([`bridge/PROTOCOL.md`](../bridge/PROTOCOL.md)).

### 1.3 채점·판정 기준 (무엇을 성공으로 볼지)

| 개입 | 내용 | 근거 |
|------|------|------|
| AND 임계 | acc ∧ macro-F1 ∧ invalid · 부분점수 없음 · 유사도 매칭 금지 | context-handoff §3 |
| Sanity floor | 상수·난수·스키마 위반 3종 전부 FAILED | 동상 |
| 임계 보정 | 가정 0.75 → 실측 후 **0.68/0.65** (조작이 아니라 측정) | 미결표 #2–3 · SD-004 |
| 전처리=계약 | 32×32 Gate·Product 동일 | D3 |
| 샘플 선택 | 모델 기반 골든 샘플 금지 | D9 · D10 |
| **등가 → 하한** | A/B `\|Δ\|<0.05`를 계약에서 **내림** (홀드아웃 반증 후) | **D17** · phase1-verdict |
| 제품 주장 정리 | «능력 → 승인 도메인 → 증적». 채점 기계가 서사 점령한 것 되돌림 | **D18** |
| Phase 1 Go | v4.6 기준 Go · **기준을 실패 뒤 바꾼 사실까지 기록** | phase1-verdict §0 |

여기가 붙임2 문구의 **「채점 규칙·판정 기준은 팀이 설계」**에 가장 직접 대응한다.

### 1.4 스스로 찾아 방향을 튼 것 (반증·발견)

보고서·판정 문서에 **결과가 나빠지는 방향**으로 남긴 것들 — AI가 “성공 수치를 예쁘게” 쓰라고 하면 보통 안 하는 종류의 개입.

| # | 발견 | 후속 |
|---|------|------|
| 1 | 골든셋이 학습셋과 겹침 | 홀드아웃 · 누출 검사 · 등가 수치 무효화 |
| 2 | A/B 등가가 누출/계약 설계 한계 | D17 — 등가를 관측값으로 강등 |
| 3 | 사용자가 Node를 **직접** 호출 | Core 중개 · 배정 검증 · 입력 바이트까지 Core |
| 4 | `trust_domain`만으로는 조직 A→B 배정 | D24 org |
| 5 | 증적에 요청자/도메인이 비어 있음 | D23 |

소감의 「동작한다 ≠ 규칙을 지키며 동작한다」와 같은 축이다.

### 1.5 출품·운영에서 사람이 한 일 (문서상 분명)

| 개입 | 내용 |
|------|------|
| 시연 촬영·CapCut 편집·YouTube | 런북은 AI가 도와도 **촬영·컷·업로드는 사람** |
| 결과보고서 문장 취향 | 실행 계층 서사·소감·기대효과 **리뷰 수정** |
| 접수 정보·포털 제출 | 팀명/인원/부문 · PDF · 포털 zip |
| master 머지 | PR까지 AI/에이전트, **main 머지는 사람** |
| 절대규칙 유지 | “막히면 제약 끄기” 거절 — CLAUDE.md |

### 1.6 이 대화에서 보인 개입 (2026-08 후반 · 출품)

세션 기록에 남는 **방향 지시** 예 (코드보다 제품 문장).

- CapNet = 모델 공유가 아니라 **실행 계층**
- “결과만 맞으면?” → **경로·자격·데이터 행방**이 문제인 맥락 질문
- 개발배경에 **유휴 자원 + 경로 관리**를 넣기 / MVP 과장(“주변 PC 다 연결”) 경계
- 소감·기대효과 문안을 **사람이 쓰고** 리뷰 요청
- AI 보조 **100%** 기입 거부 → “설계 vs 구현” 구분 요청 ← **이 문서의 계기**

## 2. AI 보조가 크게 들어간 영역 (추정)

측정된 %가 아니다. **역할 구분**용.

| 영역 | 예 |
|------|-----|
| 구현 | Core/Node FastAPI, claim, 워커, compose, 마이그레이션 DDL 초안 |
| 검증 자동화 | `scripts/demo*` · `sanity` · `check_*` · 단위 테스트 대량 |
| 문서 초안 | CHANGELOG 항 · 체크리스트 · form-draft 첫 문장 · 런북 복붙 |
| 출품 보조 | docx 칸 채우기 스크립트 · YouTube/CapCut **가이드** (편집 자체는 사람) |
| capreq 등 | 독립 모듈 스캐폴딩 (출품 Must 아님) |

AI가 초안을 내도, **제약 끄기·서명 URL·사전학습 가중치** 같은 제안은 규칙/Decision으로 **거절된 이력**이 문서에 있다 → 그것도 사람 개입.

## 3. 붙임2에 쓸 때 권장 문장

기억용 요약과 제출용 문장을 맞춰 둔다.

> Cursor·Claude Code로 코드 작성·디버깅·문서 초안을 보조했다.  
> **제품 규칙**(DB 불변식·배정 `INSERT…SELECT`·게이트는 team runner만·입력 Core 중개·품질 프로파일/하한 판정 D17·D18·보장/불보장 분리)은 팀이 설계·문서화했고, 골든셋 누출·A/B 등가 반증·직접 Node 호출 등 **실패를 인정한 뒤 계약을 개정**했다.  
> AI가 생성·수정한 코드는 팀이 동작 원리를 확인하고 `demo`·`sanity`·`demo_violations` 등으로 실행 검증한 뒤 반영했다.

비율을 넣을 경우 (신고·추정):

> 구현·문서 초안 비중은 AI 보조가 크고(추정 수십 %), **규칙·판정·범위·반증 후 개정**은 팀 결정이다. “코드 100% AI”로 적지 않는다.

## 4. 체크리스트 — “내가 개입한 기억” 대조

문서만으로 안 보이는 **개인 기억**을 채울 칸. 맞으면 ☑.

- [ ] 첫 아이디어: 유휴 GPU/PC · 데이터센터만이 아님
- [ ] “주소가 아니라 능력” 표현을 직접 고름
- [ ] M25(위반 거절)를 Must로 둔 판단에 동의/지시
- [ ] 사전학습 금지·라이선스(D6) 고수
- [ ] 브리지 Decision에 Confirm을 남긴 항목 (예: D8′ 한도·입력 경로)
- [ ] Phase 1 Go / D17 등가 포기 결정에 관여
- [ ] 촬영·영상·보고서 최종 문장
